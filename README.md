# Space Miner

A browser-based 2D space mining / tower defense game, inspired by the old Flash game "The Space Game". Build
mines next to asteroids, power them with solar panels and defend them with lasers and missile launchers while
pirates attack in waves.

Singleplayer for now. The simulation is a deterministic, framework-free package, so an authoritative
multiplayer server, more game modes and database-backed saves can be added without rewriting it.

## Requirements

- Docker with Docker Compose v2
- make

Everything else (Node, pnpm, the tools) runs in containers. On Windows, use WSL2 with Docker Desktop's WSL
integration and keep the repository in the WSL filesystem.

## Quickstart

```sh
make up
```

Then open http://localhost:5173 or https://spaceminer.localdev.hu. The first start installs the dependencies
into Docker volumes; `make logs` shows the progress. `make down` stops everything.

No `.env` is needed. To change a port, the domain or the file watcher, copy `.env.example` to `.env`.

### Local HTTPS domain

`*.localdev.hu` resolves to `127.0.0.1`. The `localdev_download` container downloads the matching certificate
into `docker/localdev/` (git-ignored, nothing to generate), and nginx serves the dev server on
https://spaceminer.localdev.hu, hot reload included. nginx completes the certificate chain on start
(`docker/nginx/15-localdev-fullchain.sh`), so curl and Node trust it too, and reloads when the certificate is
renewed.

nginx binds port 443. If another project already uses it, set `HTTPS_PORT` in `.env` (the URL then becomes
`https://spaceminer.localdev.hu:<port>`).

## Architecture

**sim vs client.** `@space-miner/sim` is plain TypeScript: its tsconfig has no DOM library and ESLint forbids
importing Phaser or Vue and using `Math.random`, `Date.now` or `performance.now` in it. The client renders the
state and turns input into commands; the same package can run unchanged on a server.

**State.** The whole game is one plain, JSON-serializable object (`GameState`): players, buildings (with what
each works on: the asteroid a mine mines, the pirate a turret aims at), asteroids, pirates, projectiles, wave
timer, PRNG state. Entity ids come from a counter in the state.

**Commands.** Every player action is a typed command (`placeBuilding`, `upgradeBuilding`, `sellBuilding`) carrying a
`playerId`; buildings have an `ownerId`. `step(state, commands)` validates each command and returns a result
with a typed rejection reason (`insufficientOre`, `cellOccupied`, `maxLevel`, ...), plus the typed events of the
tick (`shotFired`, `enemyFired`, `enemyDestroyed`, `buildingDestroyed`, `waveStarted`, ...) for sound and visual effects
and, later, for the clients of a server. `validateCommand` is
read-only, so the client uses it for the placement preview. The client gets the state as `ReadonlyGameState`
and can only change it by sending commands.

**Tick.** The simulation runs at a fixed 20 ticks per second. `GameSession` runs an accumulator loop: each frame
it runs the ticks that are due, then Phaser renders at display rate and interpolates moving objects between the
last two ticks.

**Determinism.** Randomness comes from a seeded PRNG (Mulberry32) whose state lives in `GameState`; distances
use only `Math.sqrt`, which IEEE 754 defines exactly. The same level, seed and command list always produce the
same state, and a JSON copy of the state continues identically (both are tested).

**Modes.** A `GameMode` sets up a game from a level config and a seed and evaluates the state as running, won
or lost. Modes live in a registry; `mining` is the only one so far.

**Balance and levels.** Costs, hit points, damage, ranges, fire rates, mining rates, energy, enemy stats,
bounties and wave composition are config data in `packages/sim/src/config/`, never in the logic. Levels are
data as well. `test/balance.test.ts` plays every level with a simple scripted player (`test/autoplayer.ts`) on
10 seeds: it must win every game on the first two levels and at least three games on every level, and lose
more buildings from level to level (on the ten levels: about 1, 8, 20, 21, 25, 26, 30, 33, 33 and 37 on
average). It is far from optimal, so it shows that the levels can be won and get harder. The waves of every
level are at least as strong as those of the level before it (`test/waves.test.ts`); the differences in layout,
spawn edges and wave interval do the rest.

**Vue and Phaser.** They talk through a typed event bus (`placement:select`, `selection:change`, `command`,
`command:applied`, `command:rejected`, `sim:events`, `tick`, `game:over`, `alert`, `view:change`,
`view:zoom`). `AlertMonitor` watches
the game and raises the alerts. Vue keeps plain snapshots of what it
shows, never the live state.

**Sound.** `AudioEngine` (Web Audio API) has a music bus (with a duck stage, so an alarm cuts through) and an
effects bus under a master volume and a limiter. The weapons, explosions, the wave alarm and the warp jumps are
rendered sample by sample (`src/audio/rendered.ts`) and layered like library sounds, so they sound recorded
rather than synthesized: an explosion is a clipped crack (the pressure front), a boom whose lowpass closes as
the fireball cools, a sub-bass pressure wave, a rolling rumble that differs in each ear, debris crackle
thinning out, shrapnel pinging off hulls (modal metal) and, for the big ones, secondary detonations (a building
also groans, creaks and collapses); a laser is an electrical crack, a discharge sweeping down and buzzing with
the capacitor's hum, a thump and the hiss of ionized air, with only a hint of a "zing"; pirate guns are lower
and dirtier, the dreadnought's cannon lower still; the wave alarm is a cinematic impact under a two-tone
battle-stations klaxon. A worker (`renderWorker.ts`) renders a few variants of each while the game loads
(`soundBank.ts`); they play at a slightly random pitch, so a battle never repeats one sample. The other effects
(building, upgrading, UI) are synthesized on every play (`src/audio/effects.ts`). Everything goes through a
short space reverb, and rapid-fire sounds are limited per effect. `GameAudio` turns the game's events into
effects, panned by their position on the map, pings the last three seconds before a wave and ducks the music
under the wave alarm.

The soundtrack is fixed, only its volume can be changed (or muted): `loading.*` in
`src/assets/music/` plays in the intro, the loading screens and the menu, `game.*` in a sector; while pirates
attack, the game track opens up (a lowpass opens, a little louder). The files are fetched while the game loads
and loop without the encoder's silence. Where a file is missing, the built-in soundtrack plays: "Sentinel
Expanse" (`src/audio/songs/`), written as note data and played by `SongPlayer` with synthesized instruments
(a choir pad, a low string ostinato, a horn section, film drums in its battle layer), through a mix bus
(`MusicPlayer`: rumble and harshness cut, a glue compressor, soft saturation). Browsers allow audio only after
a user gesture, so the engine starts with the click that launches the game.

**Persistence boundary.** Progress goes through the async `SaveRepository` interface, implemented by
`LocalStorageSaveRepository`, the only code that touches `localStorage`. Saves have a `schemaVersion` (2: the
audio settings were added; 3 and 4 had a soundtrack choice; 5: the soundtrack is fixed, the choice is dropped;
older saves are migrated on load). A local
player id is generated once with `crypto.randomUUID` and stored. An API + database implementation can replace
the repository without changes elsewhere.

## Game rules (mode: mining)

- 40 × 24 grid, every building takes one cell. Asteroids hold ore, the only currency. They come in three
  sizes: small and medium ones take one cell, large ones 2 × 2 cells and hold the most ore. Mine ranges are
  measured to the center of the asteroid.
- Start: the level's starting ore and a small base (solar panel, mine, laser).
- **Win:** mine at least 90% of the level's total ore (progress bar in the HUD).
- **Lose:** all your buildings are destroyed.
- Buildings, each upgradable to level 3 with ore:
  - **Mine**: extracts ore from the asteroids in range; uses energy.
  - **Solar**: produces energy.
  - **Laser**: cheap, fast, low damage, short range; uses energy.
  - **Missile**: expensive, slow, high damage, longer range, small splash; uses energy. It fires a salvo of
    one missile per level (level 3: three, a little lighter each), spread over the nearest pirates.
  - **Mender Hive**: keeps one repair drone per level. The drones fly to the damaged buildings of their owner
    in the hive's range (the most damaged first, spread over the damage), repair them from beside them and
    fly home when nothing needs repair. Upgrades bring more, faster drones. Pirates never attack drones;
    drones are entities of the simulation (`state.drones`), so what is drawn is what happens. Uses energy.
- Energy is a global balance: when consumption exceeds production, mines, turrets and hives work at the
  covered share (for example 80% power: 80% mining rate, fire rate and repair rate).
- Placement needs a free cell inside the map, no asteroid, and enough ore.
- **Selling** a building pays back 60% of everything spent on it (placing and upgrades), less if it is
  damaged. The last building cannot be sold.
- Asteroids glow in their ore color, which fades to grey as they are mined; click one to see how much ore is
  left in it.
- Pirates spawn on the map edges in timed waves, fly to the nearest building, steering around the asteroids
  in their way, and fire at it from a short range. Three ships:
  - **Raider**: fast and fragile, comes in numbers.
  - **Gunship**: the all-rounder.
  - **Dreadnought**: slow, tough, hits hard from a little further out.
- Waves start with raiders and bring in gunships and dreadnoughts later; every wave has more ships with more
  hit points, until wave 10, after which the waves stay at that strength. The HUD shows the next wave.
- A destroyed ship pays a bounty in ore to the owner of the turret that destroyed it, so the defense keeps
  paying when the asteroids near the base run dry. Bounties do not count towards the mined ore.
- Ten sectors (levels) with rising difficulty. They differ in where the base starts (west, the middle, a
  corner, the east rim), how the ore lies, which map edges the pirates come from (every side, only the east,
  the north and the south, ...: `spawnEdges` in the level config), how early the heavy ships come and how fast
  the waves follow each other. Winning a level unlocks the next one; progress is saved in the browser.

The game raises alerts: low energy, a wave coming (10 s ahead, then a ping for each of the last three
seconds), the base under attack, buildings destroyed. When a wave arrives a klaxon sounds, a banner names the
wave, its ships and where they come from, the screen edges pulse red, the view shudders, and red chevrons on the
map edges mark where the ships came in.
Lasers turn towards their target; mines show a beam to the asteroid they mine and dig with their drill arms
(`src/phaser/mineRig.ts` cuts the arms out of the mine sprites and swings them around their shoulders), solar
panels glow, turrets locked on a target light up, and every building type starts up with its own sound. Repair
drones rest on their hive, fly out with a thruster glow and weld with a flickering beam, sparks and rising
repair crosses; the hit point bar of a building under repair turns mint. Asteroids drift and spin
slowly around their cells (on screen only; the game keeps them on the grid). Behind every asteroid field lies
a soft nebula, and two layers of twinkling stars drift over the background, with a shooting star now and then
(`src/phaser/Backdrop.ts`, painted on canvases at start). The HUD shows the ore with its income per second
(spending, bounties and sales float up from it), the energy use, the mined share against the goal, the wave
timer with the ships it brings, and the pirates on the map.

Controls: keys 1–5 pick a building, a click places it, Esc or right click cancels placement. Click a building
to upgrade or sell it from the card that opens next to it (U upgrades the selected building, with the next
level's stats shown beside the current ones), click an asteroid to see its ore. The mouse wheel, the +/- keys
or the zoom buttons (bottom right) zoom in up to 350% (0 shows the whole map again); dragging with any mouse
button or the arrow/WASD keys pan, and the stars and the background follow with a little parallax
(`src/phaser/CameraController.ts`). Esc (with nothing to cancel), P or the pause button pause the game. M
mutes the sound; the speaker button (top right) has the music and effects volumes. The sound settings are
saved.

Leaving a running sector always asks first, because the session cannot be continued and the sector starts
over: the back button of the HUD, leaving or restarting from the pause menu and the browser's back button (the
app keeps one history entry while a sector is on and puts it back) open the question in the game; closing the
tab, reloading or typing another address get the browser's own question (`beforeunload`; browsers do not
show a page's own text there). Once the game is won or lost nothing is lost, so it leaves without asking.

The game opens with a loading screen over a star field (sprites, rendered sounds and music load, with
progress); a click or a key launches it (browsers need that before any sound), then a ten-second intro plays:
the drive spools up, jumps, the hyperspace tunnel, the drop out into an asteroid belt and a pirate raid shot
down by turrets out of view, in time with its sounds, then the title (`BootScreen.vue`, `src/intro/`). A click
or a key skips it; with reduced motion it is skipped. The menu shows the ten sectors with their difficulty and
state, a button that continues with the next one, and a briefing with the buildings and the controls, over a
moving space backdrop (`MenuBackdrop.vue`). Starting a sector jumps to it (`SectorLoading.vue`): the sector's
briefing (first wave, interval, where the pirates come from, starting ore, the ships and from which wave, a
tip) over a warp field that spools up, then the jump, and the game fades in from its flash.

## Art

The sprites were generated with ChatGPT as sprite sheets: one object per cell of a grid, on a transparent
background. The original sheets are in `packages/client/art/`, and `make sprites` cuts them into
`packages/client/src/assets/sprites/` (`scripts/sprites.ts`). The script finds the objects by their
outlines, not by the grid, removes the faint haze and the colored fringe of the edges, and scales them down.
`buildings.png` came with a grey glow behind every building instead of a transparent background; the glow is
a little less opaque than the buildings, so the script keeps only the pixels at least 250/255 opaque for that
sheet (`backdrop` in its sheet list).

| File             | Grid               | Contents, left to right, top to bottom                                                                                                                             |
| ---------------- | ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `sheet.png`      | 4 × 4              | mine, solar, laser, missile launcher; raider, gunship, dreadnought, laser bolt; missile, 2 small asteroids, medium asteroid; 2 medium asteroids, 2 large asteroids |
| `buildings.png`  | 4 columns × 3 rows | mine, solar, laser, missile launcher, at levels 1, 2 and 3 (one row per level)                                                                                     |
| `hive.png`       | 3 columns × 1 row  | optional: the Mender Hive at levels 1, 2 and 3                                                                                                                     |
| `background.png` | any                | the map background, copied as it is                                                                                                                                |

Every sprite is optional: where one is missing, the game draws a simple shape (a building without its level
sprite uses the one from `sheet.png`). The Mender Hive and its drone have no sheet yet: they are painted in
code (`src/game/generatedSprites.ts`), and sprites cut from `hive.png` replace them. Upgraded buildings are drawn a little bigger. Ships and projectiles are
drawn pointing up and turned towards where they fly.

## Music

The soundtrack is "Space Signal" by blemlin (intro, loading screens, menu) and "Galactic Arcade" by kissan4
(in game), both under the Pixabay Content License. Pixabay does not allow automated downloads, so they are
downloaded by hand into `packages/client/src/assets/music/` as `loading.mp3` and `game.mp3`; the README in that
folder has the links and the credits. Without them the built-in soundtrack plays.

## Roadmap

- **Multiplayer:** an authoritative server that runs `@space-miner/sim`, collects the players' commands per
  tick and broadcasts state or commands. Commands already carry a `playerId`, buildings an `ownerId`, and
  levels define one spawn per player.
- **DB-backed saves:** an API + database implementation of `SaveRepository`, with a real account id in place of
  the local player id.
- **More game modes:** new `GameMode` implementations in the registry (survival, PvP, timed challenges).
